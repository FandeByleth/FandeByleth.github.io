UNIDAD 2. ADMINISTRACION DE PROCESOS Y PROCESADOR

2.1 CONCEPTO DE PROCESO

En términos sencillos, un proceso es un programa en ejecución. Es la unidad fundamental de trabajo en un sistema operativo, la cual incluye el código del programa, sus datos actuales, las variables, los registros del procesador y el espacio en memoria asignado para que pueda funcionar

Elementos de un Proceso

Cada vez que abres una aplicación, el sistema operativo le asigna varios componentes esenciales para su ejecución:

Código: Las instrucciones del programa.

Datos: Variables, asignaciones y memoria temporal.

Contador de Programa: Indica cuál es la siguiente instrucción que debe ejecutarse.

Recursos: Memoria RAM, archivos y dispositivos de entrada/salida (como el teclado).


Identificación y Jerarquía

PID (Process ID): El sistema operativo identifica a cada proceso activo asignándole un número de identificación único.

Padre e Hijo: Los procesos existen en una jerarquía. Un proceso que abre a otro se le llama "proceso padre" y el resultado es un "proceso hijo".


2.2 ESTADOS Y TRANSICIONES DE PROCESOS

Los estados y transiciones de los procesos son las distintas etapas por las que pasa un programa en ejecución dentro de un sistema operativo. En el modelo clásico de 5 estados, el ciclo de vida abarca desde la creación del proceso hasta su finalización.


Los 5 Estados Principales

A medida que se ejecuta, el sistema operativo administra los procesos haciéndolos pasar por diferentes estados:

Nuevo: El proceso se está creando y cargando en memoria.

Listo: El proceso está esperando a que la CPU se desocupe para poder ejecutarse.

En Ejecución: El procesador (CPU) está ejecutando las instrucciones del proceso.

Bloqueado: El proceso no puede continuar porque espera a que ocurra un evento externo (como leer un archivo o la entrada del usuario).

Terminado: El proceso ha completado su ejecución o fue cancelado por el sistema o usuario.

Transiciones (Cambios de estado)

Las transiciones son los movimientos entre los estados:

Admisión (Nuevo a Listo): El sistema operativo acepta el proceso creado y lo coloca en la cola de listos.

Planificación / Despacho (Listo a Ejecución): El planificador del sistema operativo le asigna la CPU al proceso.

Interrupción / Expropiación (Ejecución a Listo): El tiempo asignado al proceso (quantum) se agota, o llega un proceso con mayor prioridad, por lo que vuelve a la cola de listos.

Bloqueo (Ejecución a Bloqueado): El proceso realiza una solicitud de entrada/salida o espera por un recurso y debe suspenderse.

Despertar (Bloqueado a Listo): El evento o recurso que el proceso estaba esperando se libera, por lo que vuelve a la cola de listos para esperar su turno de ejecución.

Salida (Ejecución a Terminado): El proceso completa su tarea con éxito o ocurre un error fatal, liberando todos sus recursos.


2.3 PROCESOS LIGEROS: HILOS O HEBRAS

Los procesos ligeros, también conocidos como hilos o hebras, son las unidades fundamentales de ejecución más pequeñas que un sistema operativo puede planificar. Permiten que un mismo programa realice varias tareas de forma simultánea, dividiendo el trabajo en secuencias independientes que comparten el mismo entorno.

A diferencia de los procesos tradicionales (que son "pesados" y totalmente independientes), los hilos pertenecen a un proceso contenedor y operan dentro de su espacio de memoria compartido.

Lo que comparten: El código, las variables globales, el espacio de memoria (Heap) y los recursos del sistema operativo (como los archivos abiertos).

Lo que tienen de forma privada: Cada hilo tiene su propio contador de programa (para saber qué instrucción sigue), sus registros y su propia pila de ejecución (Stack, para variables locales)

Ventajas de los Hilos

Eficiencia y velocidad: Crear un hilo consume mucha menos memoria y tiempo de CPU que crear un proceso nuevo, ya que no hay que duplicar todo el entorno.

Conmutación rápida: Cambiar de contexto entre un hilo y otro es mucho más veloz por la gran cantidad de recursos compartidos.

Mejora del rendimiento: Permite el paralelismo real en procesadores con múltiples núcleos, ejecutando cálculos pesados mientras la interfaz gráfica sigue respondiendo.


Diferencia entre Hilos y Procesos

Proceso: Es un programa en ejecución. Tiene su propio espacio de memoria aislado (no puede acceder a la memoria de otro proceso directamente).

Hilo: Es una "tarea" o "flujo de control" dentro de un proceso. Puede comunicarse con otros hilos fácilmente porque comparten la misma memoria.


2.4 CONCURRENCIA Y SECUENCIABILIDAD

La concurrencia es la capacidad de un sistema para ejecutar múltiples tareas de forma simultánea o superpuesta. La secuenciabilidad, por su parte, se refiere a la ejecución lineal y ordenada de procesos, uno tras otro, lo que asegura predictibilidad.

Concurrencia

Definición: Permite que varias tareas avancen al mismo tiempo, compartiendo recursos del sistema.

Ventajas: Maximiza la eficiencia del procesador y reduce los tiempos de espera.

Desafíos: Requiere sincronización. Si no se gestiona bien, pueden surgir problemas como Interbloqueos y Condiciones de Carrera.


Secuenciabilidad

Definición: Es el procesamiento lineal de instrucciones, donde un proceso no comienza hasta que el anterior ha terminado.

Ventajas: Garantiza un orden lógico, es fácil de programar, predecible y evita errores de concurrencia.

Uso: Es ideal para tareas dependientes donde el resultado de una operación es estrictamente necesario para iniciar la siguiente.

La concurrencia se encarga de gestionar múltiples tareas al mismo tiempo, mientras que la secuencialidad se enfoca en el orden estricto de ejecución.


2.5 NIVELES, OBJETIVOS Y CRITERIOS DE PLANIFICACION

Niveles de Planificación

Largo Plazo: Decide qué trabajos se admiten en el sistema para ser procesados. Controla el grado de multiprogramación.

Mediano Plazo: Transfiere procesos entre la memoria principal y la secundaria (disco) para liberar espacio y regular la multiprogramación (conocido como intercambio o swapping).

Corto Plazo (Dispatcher): Selecciona qué proceso listo debe ejecutarse a continuación en la CPU y le asigna el procesador.

Objetivos Principales

Equidad: Garantizar que todos los procesos reciban una porción justa y equitativa de tiempo de CPU y recursos.

Eficacia: Maximizar la utilización del procesador, buscando que siempre se mantenga ocupado.

Rendimiento: Maximizar la tasa de trabajos (número de procesos completados por unidad de tiempo).

Criterios de Planificación

Criterios para Evaluar la Planificación
Son métricas específicas que permiten evaluar si un algoritmo de programación o una estrategia de trabajo está funcionando correctamente:

Utilización de la CPU: Porcentaje de tiempo que el procesador (o recurso clave) se encuentra ocupado.

Rendimiento (Throughput): Cantidad de procesos o tareas que se completan con éxito por unidad de tiempo.

Tiempo de Retorno (Turnaround Time): Tiempo total que transcurre desde que se envía un proceso o tarea hasta que se completa.

Tiempo de Espera: Suma de los tiempos que un proceso o proyecto pasa esperando en una cola o en pausa por falta de recursos.

Tiempo de Respuesta: Tiempo que tarda el sistema en comenzar a producir la primera salida o resultado visible desde que el usuario realiza una solicitud


2.6 TECNICAS DE ADMINISTRACION DE PLANIFICADOR

El planificador de procesos es el componente del sistema operativo que decide qué proceso utiliza la CPU y durante cuánto tiempo. Su objetivo principal es maximizar la eficiencia, la equidad y el tiempo de respuesta del sistema

Métodos No Apropiativos (No Expropiativos)
Una vez que el planificador asigna la CPU a un proceso, este la retiene hasta que finaliza su ejecución o se bloquea voluntariamente (por ejemplo, al esperar una operación de entrada/salida).

FIFO (First In, First Out / Primero en Entrar, Primero en Salir): Los procesos se ejecutan en el mismo orden exacto en el que llegaron a la cola de listos. Es muy justo, pero poco eficiente si un proceso corto debe esperar detrás de uno muy largo.

SJF (Shortest Job First / El trabajo más corto primero): Asigna la CPU al proceso con el tiempo de ejecución estimado más corto. Reduce drásticamente el tiempo de espera promedio, pero puede provocar inanición (espera infinita) para procesos largos.

Métodos Apropiativos (Expropiativos)
El sistema operativo puede interrumpir un proceso que se está ejecutando y asignarle la CPU a otro, basándose en prioridades o límites de tiempo. Son ideales para sistemas multitarea.

Round Robin (Turno Rotatorio): Es el algoritmo más utilizado. Asigna a cada proceso un pequeño intervalo de tiempo llamado cuanto (quantum). Si el proceso no termina en ese tiempo, se le retira la CPU y se coloca al final de la cola. Garantiza equidad y buenos tiempos de respuesta.

SJF Apropiativo: Similar al SJF no apropiativo, pero si llega un proceso nuevo con un tiempo de ejecución menor al restante del proceso actual, el sistema lo sustituye de inmediato.

Por Prioridades: Se asigna un valor de prioridad a cada proceso. La CPU se le otorga al proceso con la prioridad más alta. Para evitar que procesos de baja prioridad nunca se ejecuten, se utiliza la técnica de envejecimiento (aumentar gradualmente la prioridad de los procesos antiguos).

Técnicas Avanzadas (Colas Multinivel)
Combinan múltiples algoritmos para manejar diferentes tipos de procesos (interactivos, en segundo plano, por lotes).

Colas Multinivel: Dividen la cola de listos en varias colas independientes (ej. Primer plano vs. Segundo plano), donde cada cola puede tener su propio algoritmo de planificación (ej. Round Robin para procesos interactivos, FIFO para lotes) y una prioridad estática.

Colas Multinivel con Realimentación: Similar al anterior, pero permite que los procesos se muevan entre diferentes colas. Los procesos que consumen mucho tiempo de CPU son degradados a colas de menor prioridad, favoreciendo a los procesos cortos e interactivos
