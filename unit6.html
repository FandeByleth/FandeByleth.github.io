UNIDAD 6. PROTECCION Y SEGURIDAD

6.1 CONCEPTO Y OBJETIVOS DE PROTECCION Y SEGURIDAD

La protección se refiere a los mecanismos internos y políticas diseñadas para controlar qué usuarios, programas o procesos pueden acceder a determinados recursos. La seguridad, por su parte, abarca las medidas globales destinadas a proteger los activos (personas, datos o infraestructuras) contra amenazas, ataques o incidentes externos.

Objetivos principales

Disuasión: Mostrar fortaleza para evitar que un atacante intente vulnerar el sistema.

Detección: Descubrir y alertar de manera temprana sobre accesos no autorizados o fallos.

Demora: Implementar barreras u obstáculos que retrasen el avance de una amenaza.

Protección de la Información: Garantizar la confidencialidad, integridad y disponibilidad de los datos.

Prevención y Respuesta: Limitar el daño y establecer planes de acción ante cualquier incidente


6.2 CLASIFICACION APLICADA A LA SEGURIDAD

La clasificación aplicada a la seguridad informática es el proceso de categorizar medidas, activos y riesgos para proteger la información y los sistemas. Permite optimizar recursos y aplicar controles precisos según la criticidad de los datos.

Según la naturaleza de los activos protegidos

Hardware: Protección física de servidores, equipos y centros de datos (ej. control de accesos, sistemas anti-incendios).

Software: Blindaje de programas, aplicaciones y sistemas operativos (ej. firewalls, antivirus, gestión de parches).

Redes: Salvaguarda de la infraestructura de telecomunicaciones.

Nube: Protección de entornos virtuales, almacenamiento remoto y API's

Según el momento de actuación

Seguridad Activa: Acciones preventivas para evitar daños antes de que ocurran (ej. cifrado, contraseñas seguras, software de seguridad).

Seguridad Pasiva: Medidas para minimizar el impacto o restaurar el sistema tras un incidente.

Según el origen y alcance

Seguridad Física: Protección del entorno y las instalaciones contra desastres naturales, robos o sabotajes.

Seguridad Lógica: Aplicación de barreras y protocolos de acceso a nivel digital (ej. permisos de usuario, autenticación)

Clasificación de la información (por sensibilidad)

Pública: Información de acceso libre o divulgación autorizada.

Interna: Datos de uso exclusivo para empleados, sin repercusión grave si se filtran.

Confidencial: Información de alto valor (financiera, estratégica o patentes).

Restringida / Secreta: Datos críticos sujetos a estrictas regulaciones o leyes de protección (ej. datos médicos o de seguridad nacional).


6.3 FUNCIONES DEL SISTEMA DE PROTECCION

Un sistema de protección regula el acceso de usuarios, programas o procesos a los recursos de un entorno. Sus funciones clave son: prevenir accesos no autorizados, asegurar la integridad de la información, y garantizar que cada elemento utilice únicamente los recursos permitidos por las políticas establecidas.

Aislamiento de procesos: Protege los procesos del sistema contra las acciones de los usuarios y aísla los procesos de diferentes usuarios entre sí.

Control de memoria: Previene el acceso no autorizado a áreas de memoria principal que no corresponden a un proceso en ejecución.

Gestión de dispositivos: Controla quién o qué tiene permiso para utilizar el hardware del sistema.

Autenticación: Implementa mecanismos como contraseñas o biometría para verificar la identidad antes de otorgar acceso.


6.4 IMPLEMENTACION DE MATRICES DE ACCESO

Una matriz de acceso es un modelo de seguridad que define qué permisos tiene cada usuario o proceso sobre los recursos de un sistema. Funciona como una tabla de doble entrada: las filas representan a los sujetos (usuarios) y las columnas a los objetos (archivos, carpetas, bases de datos).

Sujetos: Las entidades que solicitan acceso (ej. usuarios, aplicaciones, procesos).

Objetos: Los recursos digitales o físicos que se desean proteger (ej. directorios, bases de datos).

Derechos (Permisos): Las acciones permitidas (ej. lectura \(R\), escritura \(W\), ejecución \(X\), o modificación).

Para llevar esta matriz teórica a la vida real, los sistemas utilizan dos enfoques principales:

Listas de Control de Acceso (ACL): Se agrupan los permisos por objeto (se adjunta a cada archivo la lista de usuarios que pueden acceder y qué pueden hacer).

Listas de Capacidades: Se agrupan los permisos por sujeto (a cada usuario se le entrega una "llave" o lista de los recursos a los que tiene derecho).


6.5 PROTECCION BASADA EN EL LENGUAJE

La protección basada en el lenguaje es un enfoque de seguridad informática donde las políticas de control de acceso y uso de recursos se especifican directamente en el código fuente mediante el lenguaje de programación. El compilador o el intérprete se encargan de hacer cumplir estas reglas en lugar de depender exclusivamente del Sistema Operativo.

Características clave

Control a nivel de aplicación: Permite al desarrollador definir exactamente qué datos y recursos pueden ser accedidos o modificados por diferentes partes de su software.

Cumplimiento estricto: El compilador verifica el código antes de ejecutarlo para prevenir el acceso no autorizado o el mal uso de la memoria.

Seguridad dinámica: El entorno de ejecución del lenguaje vigila y controla los accesos en tiempo real para bloquear operaciones peligrosas.

Este paradigma es fundamental en lenguajes modernos y entornos de programación que gestionan la seguridad de forma nativa para evitar fallos comunes (como desbordamientos de búfer):

Java: Utiliza un modelo de sandboxing (caja de arena) y firmas digitales para asegurar que los applets o programas descargados no realicen acciones maliciosas en el equipo local.

Rust: Su diseño impide el acceso inseguro a la memoria y las condiciones de carrera (race conditions) desde el momento de la compilación.

JavaScript: Implementa políticas estrictas en el navegador (como la Política de Seguridad de Contenido o CSP) para evitar la inyección de código.


6.6 VALIDACION Y AMENAZAS AL SISTEMA

La validación de sistemas es el proceso de verificar que un software cumple estrictamente con los requisitos para los que fue diseñado. Su objetivo es prevenir fallos y bloquear el paso a las amenazas (situaciones o eventos maliciosos), reduciendo las vulnerabilidades y protegiendo la integridad operativa.

Cualquier evento, lógico, físico o personal, que pueda aprovechar una debilidad (vulnerabilidad) para comprometer la seguridad. Las más comunes incluyen:

Malware y Ransomware: Software malicioso diseñado para dañar, infiltrar o secuestrar información solicitando un rescate.

Ataques de Denegación de Servicio (DDoS): Saturación de los recursos de un servidor mediante múltiples equipos infectados (botnets) para inutilizar el sistema.

Phishing e Ingeniería Social: Manipulación psicológica de los usuarios para robar credenciales o infectar el sistema.

Vulnerabilidades de Software: Errores de programación que permiten ataques como inyecciones SQL o secuencias de comandos entre sitios (XSS).


6.7 CIFRADO

El cifrado (o encriptación) es un proceso matemático que codifica la información para volverla ilegible a cualquier persona que no cuente con la clave o autorización adecuada. Actúa como un candado virtual para proteger datos tanto en su almacenamiento como en su transmisión por internet.

Los métodos de protección se dividen en dos sistemas principales:

Cifrado Simétrico: Utiliza una única clave secreta tanto para cifrar como para descifrar. Es muy rápido, por lo que suele emplearse para proteger bases de datos y archivos locales.

Cifrado Asimétrico: Utiliza un par de claves: una pública (para cifrar, que todos pueden conocer) y una privada (para descifrar, que solo tú conoces). Garantiza mayor seguridad en redes abiertas como internet.
